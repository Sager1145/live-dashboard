# 全页面 UI 设计分析

审查日期：2026-09-23。范围：当前工作区 iOS 页面、弹层、共享组件，以及保留的可选管理后台。此次只新增审查文档，没有修改产品代码。

采用 apple-like-ui、ios-dev 的设计审查方法：内容层级、操作可发现性、视觉一致性、状态反馈、文字与适配。依据是当前源码；视觉证据为 9 月 22 日历史首页截图和本次读取的 LiveDashboard-UITests 模拟器票务页画面。旧首页截图不代表当前版本。模拟器窗口随后不可用，未完成全部页面的实机走查，也未验证安装包与工作区完全一致。大字体、深色、iPad、VoiceOver 和对比度数值均未实测，以下相应内容属于待验证风险。

## 总体判断

基础方向成立：原生导航与表单、系统字体、语义颜色、统一卡片、官方图片和来源、明确空状态，以及部分大字体和减少动态效果支持，都值得保留。问题主要是信息优先级：现在更像完整资料阅读器，用户要快速判断“哪场值得看、什么时候截止、下一步做什么”时，仍需穿过很多同级信息。

建议保留现有视觉语言，先调整信息和操作层级。不要把这次改进变成全面更换圆角、配色或增加玻璃效果。

## iOS 逐页面分析

| 页面/界面 | 已有优点 | 主要问题与具体调整 |
|---|---|---|
| 演出首页 | 官方主视觉形成识别；搜索、筛选、刷新和错误恢复齐全 | 单卡同时承载封面、企划、状态、长标题、售票标签、团体、日期、场馆、截止、价格及 DAY 标签，阅读成本高。优先显示标题、日期/场馆、当前售票状态和明确的下一事项；将重复团体、完整场次标签降级。截止文字不宜与普通元数据同样弱化。16:9 裁切需用竖版海报核对主体完整性。 |
| 往期 | 独立入口且复用首页语言，学习成本低 | 历史查找与未来决策任务不同，建议优先年份、月份、场馆和回顾信息；较紧凑的列表能提高查找效率。保留仍有效的配信/回看入口，不要仅因现场已结束就将全部状态弱化。 |
| 筛选弹层 | 原生 Form，条件分组清楚 | 筛选被分散在搜索、年/月栏和弹层三处，缺少统一条件概览。应显示匹配数量与已选条件；解决上表日期默认值和重置语义。 |
| 我的 | 简洁 List，适合重复查看 | 现在仅关注列表，未来与往期未形成明显分组；下一事项被拼入 caption，且没有具体事项名称。建议分为近期待办、即将参加、已结束；截止事项独立成行，标明申请/付款/回看等类型。接通空状态入口。 |
| 详情公共框架 | 场次/分区吸顶，关注、参加、提醒有统一位置，操作行有 ViewThatFits | 长官方标题、大标题、两层选择器、三项操作、官网链接、公告占据较多前置空间。将日期/会场/当前场次做成紧凑摘要，让选中分区内容更快出现。AI、翻译、历史等工具栏动作应保持明确命名。 |
| 场次选择 | 单场隐藏，多场用水平选择条，选中状态与触感明确 | 标签拼接日期、DAY、副标题、站名，巡演会产生很长的胶囊。建议缩短到日期+场次，在下面展示完整会场；长巡演可用“选择场次”列表，并显示当前第几场。 |
| 概要 | 时间、会场、出演、票价、入场条件按卡片分组；原文可追溯 | 同级卡片削弱时间/会场的重要性。先呈现核心日程，票价和入场规则使用摘要后展开；AI 摘要应支持快速折叠，避免长摘要挤走官方核心事实。 |
| 售票 | 已结束受付可折叠；票务、特典、配信资料完整 | 实际画面中长特典说明与大图占据多屏，配信卡随后出现。默认优先仍可操作的受付/配信和最近截止；特典保留一行摘要、缩略图与展开。每张轮次卡明确一个主要动作，个人申请状态使用独立区域。 |
| 座位 | 区分公演图和场馆通用图；支持原图查看 | 图片用途应成为最醒目的标识，如“本场官方座位图”“场馆参考图”；在图片前显示适用场次与来源，避免把通用图当作本场实际配置。长图、加载失败与无图状态需分别走查。 |
| 周边 | 批次、地点、时间、资格、商品、媒体与链接均能展示 | 批次内完整说明与商品图片容易形成超长卡。先给贩售方式、截止/开始时间、资格和官方入口，商品清单与规则按需展开。不同批次保持清楚分隔，避免每个链接都争夺主操作地位。 |
| AI 摘要卡 | 明示非官方、过期状态；支持紧凑/详细与分类重点 | 摘要内部的多种颜色、类别与重点不应超越官方日期和状态的层级。默认突出少数高价值结论，保留完整摘要入口；未登录状态以简短说明和明确设置路径呈现。 |
| 官方链接区 | 保留官网标签及域名，来源可辨认 | 多个带边框链接纵向堆叠时视觉重量过高；主要申请/购买入口单独突出，其他来源使用紧凑链接行。长标签与命中区域需设备验证。 |
| 图片全屏查看 | 黑色背景突出内容，支持缩放、分享及辅助功能缩放动作 | 底部直接常驻完整图片 URL 和来源 URL，会挤压图像区域，长地址尤其明显。改为“原图/官方来源”短标签，把完整地址放入展开信息；加载失败增加页内重试。 |
| 更新与来源弹层 | 将事实证据与内容阅读分开，证据可展开 | 来源状态直接显示 rawValue，字段名也偏技术；仅显示前 20 条证据而无更多入口。使用用户语言解释状态，按时间/票务/周边分组，明确显示条目数量和更多入口。 |
| 设置首页 | 原生 Form、分组与状态反馈成熟 | 大量长 footer 让设置接近说明书；历史抓取表单位于显示与语言设置之前，“App 语言”放在提醒分组。建议日常显示/语言/提醒优先，数据更新及历史下载进入二级页，说明改为短摘要和详细说明入口。 |
| 全局卡片设置 | 按分区组织，支持恢复默认和重排 | 展开每一项才能知道状态，缺少效果预览；同一行既用于展开又参与排序，操作负担较重。收起时显示状态摘要，密度提供小样式预览，并移除不适用字段。统一“概要/总览”等术语。 |
| ChatGPT 助手设置 | 登录状态、连接测试、自动生成、清除数据都有反馈 | 未登录时仍展示模型、测试和大量配置；ChatGPT 与 API Key 入口同级出现，对普通用户过于技术化。先突出主要登录方式，将 API Key 作为另一种连接方式展开；连接后再呈现模型与自动整理。 |
| 模型选择页 | 系统选择器，支持自定义 | 原始模型 ID 缺少用途提示，按字母排序不能表达推荐顺序；保留 ID 的同时给默认推荐项和简短用途说明，自定义置后。 |
| 助手高级设置 | 已收进二级页面 | “高级”标题过泛，Client ID/回调地址缺少可扫描的用途说明。改为“高级连接设置”，清晰区分默认值和自定义值，展示恢复默认操作。 |
| 翻译目标语言选择 | 使用系统导航选择器，复杂度适当 | 保持简洁；确认“跟随 App”“关闭翻译”和具体语言的区别，当前选择与首次语言包下载反馈需要实际设备走查。 |

## 全局设计一致性

- 字体：继续使用系统语义字号；“当前截止/下一事项”不应降到 caption。长官方名称保持可读，但列表与详情可采用不同信息密度。
- 色彩：保留语义状态色，红色只表达失败、风险等明确含义。系统 tint 同时用于选择、关注、链接时，以文字和形状补充区别。未测量实际对比度，不宣称通过 AA。
- 间距与容器：现有 16pt 卡片内边距和 16pt 间距较一致；优先减少卡内层级，而非继续加容器。说明、链接、图片、操作不能全部同等醒目。
- 动效：已有 Reduce Motion 支持；图片缩放等 UIKit 动画需另外核对。日常切换和筛选保持快速，不增加装饰性入场动画。
- 适配：首页网格最小 340pt，加两侧内边距后，对 320/窄窗口存在溢出风险；详情四段 Picker、长场次胶囊、左右 LabeledContent 是大字体重点检查对象。这里只标记风险，未把它们视作已复现错误。
- 状态：区分“官网未公布”“资料尚未获取”“网络失败”“当前筛选无结果”“用户隐藏内容”，分别给对应下一步。

## 可选管理后台

此部分为代码审查，未启动服务或检查浏览器渲染；主应用改进优先。

| 路由 | 问题与建议 |
|---|---|
| 共享布局 `server/src/api.ts:32` | 固定浅色、导航无当前状态、无窄屏断点，两列比较不适应窄屏。增加语义 token、导航选中态、可换行导航和单列断点；保留浏览器默认键盘焦点，实测后再补强自定义焦点样式。 |
| `/admin` | 审核队列与提交 JSON 表单竞争；将队列作为主任务，展示待审数量/空状态，将提交候选降级。见 `api.ts:483`。 |
| `/admin/reviews/:id` | 双列完整 JSON 难以快速比较，核验/发布/拒绝同样醒目。优先结构化字段差异与证据，JSON 折叠；区分发布与拒绝的视觉层级。见 `api.ts:512`。 |
| `/admin/snapshots/:id` | 两块 pre 缺少分组标题。增加元数据/正文标题、来源与时间、返回审核路径。见 `api.ts:556`。 |
| `/admin/events` | 每条版本都常驻回滚和撤回表单。列表保留版本/状态，操作进入详情，撤回明确破坏性语义。见 `api.ts:664`。 |
| `/admin/sources` | 健康摘要、策略 JSON、编辑操作混在一起；文档表缺少表头。摘要优先，策略折叠，表格补表头和操作列。见 `api.ts:722`。 |
| `/admin/operations` | 任务、通知和候选均为原始 JSON；改成类型/状态/数量表格，优先突出失败与积压。见 `api.ts:823`。 |
| `/admin/reports` | 仅展示公演 ID 与正文，缺时间/处理状态/下一步。显示关联公演、时间与处理入口；增加空状态。见 `api.ts:846`。 |
| 媒体版本与契约端点 | `/admin/media/:id/versions/:version` 返回原媒体或 PDF 下载；`/admin/contract` 返回 JSON schema，均非独立设计页面，不按缺少 App 布局扣分。 |

## 建议实施顺序与验证

1. 先修复入口、反馈语义、无效设置和辅助技术状态遗漏；验证空关注、单卡刷新成功/失败、各类型字段设置、售票徽章朗读。
2. 调整首页/详情/售票的信息顺序；使用单场、多日、长巡演、截止临近、长特典资料的真实样本比较。
3. 整理设置架构、来源面板、图片信息层；保证缩略图、来源和完整原文仍可访问。
4. 走查小屏、常规 iPhone、iPad/窄窗口、深色、最大辅助字号、VoiceOver 和减少动态效果；检查视觉截断、控件命中区域、状态对比度与朗读顺序。

本报告没有进行实现或回归测试，也没有为未走查的页面提供外观通过结论。
