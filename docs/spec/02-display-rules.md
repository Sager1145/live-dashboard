# 显示规则

## 首页卡片：只回答五个问题

| 用户的问题 | 卡片内容 | 数据来源 |
|---|---|---|
| 这是什么公演？ | 简称、企划／团体标签、主视觉缩略图 | `event.shortName`、`groups`、`keyVisualImageId` |
| 哪天、在哪里？ | 日期或下一站、城市／场馆、多日或多站数量 | 当前关注 `performance` / `stop` |
| 我现在能做什么？ | 正在受付、即将开售、通贩受付、配信购买 | `salesRounds[].platformStatus`、`merchBatches[].status`、`streams[]` |
| 最近什么会截止？ | 当前关注场次的最近一个重要截止 | 各 `*Window.closesAt`，按 `appliesTo` 过滤 |
| 有什么改变？ | 新受付、新物贩图、时间变更、取消／延期 | `notices[]`、`images[].contentFingerprint` 变化 |

一张首页卡只显示一个截止时间，其他进入详情。

### 首页状态四维度

```text
performanceLifecycle | ticketRoundStatus | goodsCampaignStatus | streamingStatus
```

四个维度独立计算。现场票 `sold_out` 不使整张卡不可操作；公演 `ended` 不隐藏仍有效的配信与通贩。

### 首页合并规则

| 结构 | 首页 | 详情第一层 |
|---|---|---|
| `single` | 一张卡，无 Day 选择器 | 直接四个 Tab |
| `multi_day` | 一张卡，标注 N DAYS | Day 选择 |
| `editions` | 一张系列父卡，优先显示未来版本，已举行版本折叠 | 版本选择 → Day |
| `tour` | 一张巡演卡，显示“当前关注：某站” | 站点选择 → Day |
| `mixed_event_tour` | 父卡标注“混合活动巡回”；Live 筛选只显示 `performanceType = live` 的子活动 | 活动类型 → 站点 |

## 详情页结构

```text
公演完整名称
当前版本／站点／场次副标题
[ 版本或站点选择 ]    [ 日期／Day／昼夜场选择 ]
[ 概要 | 售票 | 座位 | 周边 ]
```

- **售票** 内分：现场购票｜官方票务转售｜配信购票。配信地区限制只出现在配信卡片。
- **座位** 分四类：本公演座位图（可代表本场配置，标注适用日期和版本）、场馆参考座位图（不可代表本场）、站立区域说明、我的座位（用户手动输入）。
- **周边** 内分：通贩、场贩、线上预订会场领取。商品列表默认折叠，单件库存独立于批次状态。
- 商品一览图保留完整长宽比，支持全屏缩放，不裁成横向封面。

取消、延期等重大状态固定出现在标题区（`event.majorStatusBanner`），不依赖普通卡片是否被隐藏。

## 稀疏资料时的显示

只发布有证据的字段。字段为 `Unknown` 时：

> 已获取日程与受付开始时间。其他资料待核验。

不生成虚构票价、物贩期限或座位图；`not_fetched` / `parse_failed` 不得写成“官方没有发布”。

## 重要信息卡片默认排序

| 情况 | 优先显示 |
|---|---|
| 即将申请截止 | 当前受付卡 |
| 已抽中需记录付款 | 用户的付款提醒卡（用户自建，不冒充官方订单状态） |
| 临近演出 | 开场／开演、会场、入场要求、场贩时段 |
| 出现新座位图或新物贩图 | 更新提示卡 |
| 公演结束但配信／通贩未结束 | 配信和商品卡 |
| 所有有效期限均已过去 | 历史概要、图片与官方来源 |

## 用户卡片配置

每张信息卡的设置至少包含：

```text
visible | sortOrder | pinned | density | selectedFields
changeNotifications | deadlineNotifications | 仅本公演生效／设为默认
```

隐藏某张票务卡不删除官方数据；恢复显示后仍获取最新内容。
